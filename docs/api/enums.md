## 1. Enums الأساسية

### 1.1 `user_role` — دور المستخدم

| القيمة | المعنى | إنشاء الحساب | ملاحظات |
|--------|--------|--------------|---------|
| `idea_owner` | صاحب فكرة | تسجيل عام أو OAuth (اختيار الدور عند أول دخول) | يمكنه رفع المشاريع وإدارة طلبات الاهتمام |
| `investor` | مستثمر | تسجيل عام أو OAuth (اختيار الدور عند أول دخول) | يمكنه البحث وإبداء الاهتمام وحفظ المشاريع |
| `admin` | مشرف | **Seeder فقط — لا تسجيل عام** | لوحة التحليلات والتصدير CSV |

- `users.role` (SRS-DB-01) — **قابل للتعديل مرة واحدة فقط** عندما يكون `null` (حالة أول دخول OAuth قبل اختيار الدور). بعد التعيين لا يُغيّر عبر API في MVP.
- MVP لا يتضمن أدوار `freelancer` أو `organizer` (مؤجلة v1.1+).

### 1.2 `project_status` — حالة النشر (Publication State)

| القيمة | المعنى | الظهور |
|--------|--------|--------|
| `draft` | مسودة — مرئية لمالكها فقط | لا تظهر في المعرض ولا في نتائج البحث |
| `published` | منشور — ظاهر للجميع | تظهر في المعرض والبحث (الوضع الافتراضي عند الإنشاء) |
| `archived` | مؤرشف — مخفي من المعرض | تظهر لمالكها في لوحة التحكم فقط، تُحفظ البيانات كاملة |

- `archived` يختلف عن الحذف المؤقت (Trash): الأرشيف يحفظ المشروع مع إمكانية إعادة النشر، بينما Trash حذف مع عدّ 30 يوماً للحذف النهائي.

### 1.3 `project_state` — حالة المشروع (Lifecycle State — SRS-F02-01)

حقل `status` في جدول `projects` (SRS-DB-03) كما ورد في SRS — يُعرض على بطاقة المشروع:

| القيمة | المعنى | الترجمة |
|--------|--------|---------|
| `completed` | المشروع مكتمل | مكتمل |
| `needs_development` | يحتاج تطويراً | يحتاج تطوير |
| `needs_funding` | يحتاج تمويلاً | يحتاج تمويل |

> **ملاحظة توافق:** `project_status` (نشر/مسودة/أرشيف) هو حقل إدارة عرض؛ `project_state` (مكتمل/تطوير/تمويل) هو حالة المشروع التجارية. الحقلان منفصلان. تعديل `project_state` من الحقول الجوهرية التي تقترح إعادة التقييم (SRS-F04-02).

### 1.4 `visibility_level` — مستوى الإفصاح عن تقرير التقييم

مصفوفة الإفصاح (SRS-F05-05 + design-decisions §5.2):

| المستوى | من يراه | ماذا يرى من تقرير AI |
|---------|---------|----------------------|
| `1` | زائر غير مسجّل | التقييم الكلي (`overall_score`) فقط |
| `2` | أي مستخدم مسجّل الدخول (غير مالك) | الكلي + درجات الأبعاد الخمسة + بيانات الرسم الراداري |
| `3` | صاحب المشروع **دائماً** + المستثمر **بعد قبول طلب الاهتمام** | كل شيء: فجوات، توصيات، مهارات، SWOT، تصدير PDF |

- يُرجع كل استجابة تفاصيل مشروع الحقل `visibility_level` بالقيمة الفعلية المطبقة (1 أو 2 أو 3).
- PDF التقرير (`SRS-API-48`) متاح فقط لمستوى `3`.

### 1.5 `interest_status` — حالة طلب الاهتمام

| القيمة | المعنى | ملاحظات |
|--------|--------|---------|
| `pending` | معلق بانتظار قرار صاحب الفكرة | الوحيدة القابلة للإلغاء من المستثمر |
| `accepted` | مقبول — يُنشأ مستند PDF ويُكشف البريد | `agreement_id` يُربط |
| `rejected` | مرفوض — مع سبب اختياري | `rejection_reason` |
| `cancelled` | ملغي — من المستثمر أو بعد القبول (UC-07 E2) | الطلب الملغى لا يُحتسب في المتابعة |

- **منع التكرار (SRS-F08-03):** لا يجوز لمستثمر إرسال طلب لمشروع له طلب نشط (`pending`/`accepted`). الطلب المرفوض أو الملغى يسمح بإرسال جديد.
- قبول/رفض طلب `cancelled` → خطأ `409 INTEREST_CANCELLED` (UC-06 E3).

### 1.6 `evaluation_status` — حالة تقييم AI

| القيمة | المعنى | ملاحظات |
|--------|--------|---------|
| `processing` | قيد المعالجة في Queue | يُحدَّث عبر WebSocket عند الاكتمال |
| `completed` | اكتمل بنجاح | يُظهر للمقارنة (آخر 5 ناجحة فقط في الواجهة) |
| `failed` | فشلت كل محاولات المعالجة | محفوظة للتدقيق — زر إعادة المحاولة |
| `partial` | نتيجة جزئية (اكتملت 3 من 5 أبعاد ضمن سقف 180 ثانية) | تُعامل كـ `completed` للعرض مع تحذيرات |

- سياسة الاحتفاظ (SRS-DB-05): سجل كامل بلا حذف تلقائي؛ واجهة المقارنة تعرض آخر **5 `completed`** فقط؛ الفاشلة محفوظة للمشرف.

### 1.7 `interest_type` — نوع الاهتمام (إلزامي في طلب الاهتمام)

| القيمة | المعنى |
|--------|--------|
| `investment` | استثمار |
| `technical_development` | تطوير تقني |
| `consultation` | استشارة |

### 1.8 `file_type` — نوع ملف المشروع

| القيمة | المعنى | الحد |
|--------|--------|------|
| `image` | صورة (JPG/PNG/WebP) | 5 ملفات × 5MB لكل مشروع |
| `pdf` | مستند PDF | 3 ملفات × 10MB لكل مشروع |
| `document` | مستند (محجوز مستقبلاً — غير مقبول في MVP) | — |

- التحقق: MIME حقيقي وليس الامتداد (SRS-NFR-08)؛ منع الملفات القابلة للتنفيذ نهائياً.

### 1.9 `video_provider` — مزود الفيديو

| القيمة | المعنى |
|--------|--------|
| `youtube` | YouTube |
| `vimeo` | Vimeo |

- رابط واحد كحد أقصى لكل مشروع؛ التحقق من صحة الرابط (URL Validation)؛ العرض عبر Embed.

### 1.10 `analysis_type` — نوع تحليل وكيل AI

| القيمة | المعنى |
|--------|--------|
| `competitive` | تقرير تنافسي (ميزة تنافسية + حصة سوقية محتملة) |
| `swot` | تحليل SWOT (4+ نقاط لكل فئة) |
| `market` | تقرير سوقي |
| `comparison` | مقارنة بـ 3-5 مشاريع مشابهة في نفس المجال |

### 1.11 `model_used` — مزود AI الذي أجرى التقييم فعلياً

| القيمة | المعنى |
|--------|--------|
| `openai` | OpenAI API (الأساسي) |
| `claude` | Claude API (الاحتياطي — Fallback) |

### 1.12 `category` — مجال المشروع (قائمة مفتوحة قابلة للتوسيع)

قائمة مقترحة للـ dropdown (قابلة للإدارة لاحقاً):

`fintech`، `healthtech`، `edtech`، `ecommerce`، `saas`، `ai`، `agritech`، `logistics`، `real_estate`، `energy`، `gaming`، `social`، `marketplace`، `other`

- تُخزَّن كسلسلة نصية؛ تُفهرَس في Meilisearch؛ لا قيود إضافية في MVP.

### 1.13 `notification` — الحقول المميزة

| الحقل | القيم | المعنى |
|-------|-------|--------|
| `is_critical` | `true` / `false` | `true` = حدث حرج يُرسل عبر WebSocket (طلب اهتمام جديد، اكتمال تقييم)؛ `false` = يُحدَّث عند إعادة التحميل فقط |
| `read_at` | `null` / ISO-8601 | `null` = غير مقروء |

### 1.14 `user_profiles` — حقول الملف الشخصي حسب الدور (SRS-DB-02)

| الدور | الحقول |
|-------|--------|
| `idea_owner` | `bio`, `avatar_url`, `skills (JSON[])`, `social_links (JSON)`, `university`, `major` |
| `investor` | `bio`, `avatar_url`, `investment_focus`, `investment_range (JSON {min, max})`, `preferred_sectors (JSON[])` |

## 2. الثوابت (Constants)

### 2.1 الأمان والمصادقة

| الثابت | القيمة | المصدر |
|--------|--------|--------|
| صلاحية رمز OTP | **دقيقة واحدة** | SRS-F01-02 · design-decisions §4 |
| إعادة إرسال OTP | رمز جديد (صلاحية دقيقة واحدة) — محدد بـ 3/دقيقة | UC-01 A2 |
| صلاحية رابط إعادة التعيين | **ساعة واحدة** | SRS-F01-04 |
| صلاحية توكن Sanctum | **24 ساعة** (تجديد تلقائي عند الاستخدام) | SRS-NFR-07 |
| معدلات المصادقة | register 3/دقيقة · login 5/دقيقة · logout 10/دقيقة · verify 3/دقيقة · forgot 2/دقيقة · reset 2/دقيقة · oauth 5/دقيقة | rate-limiting-spec §3.1 |

### 2.2 التحقق من صحة المشروع (SRS-F02 + SRS-5.4.6.2)

| الحقل | الحد | ملاحظات |
|-------|------|---------|
| `title` | 5–120 حرفاً (اقتراح) | إلزامي |
| `description` | **50–2000 حرف** | إلزامي |
| `tags` | **حتى 10 علامات** | اقتراحات بالإكمال التلقائي |
| `github_url` | رابط واحد | اختياري |
| `video_url` | رابط واحد — YouTube/Vimeo فقط | اختياري |
| `budget_min` / `budget_max` | `NUMERIC(10,2)` | اختياري؛ `budget_min <= budget_max` |
| `business_info` | حتى 1000 حرف | اختياري (مدخلات التقييم) |
| فريق المشروع | حتى 10 أعضاء | من الملف الشخصي — مدخلات التقييم |

### 2.3 حدود الملفات (SRS-F02-02)

| النوع | العدد الأقصى لكل مشروع | الحجم الأقصى | الصيغ |
|-------|----------------------|--------------|-------|
| صور | 5 | 5MB لكل صورة | `jpeg`, `png`, `webp` |
| PDF | 3 | 10MB لكل ملف | `pdf` |

- الحفظ في Local Disk (`FILESYSTEM_DISK=public`) — لا S3/R2 في MVP.
- رفع الصور الشخصية (`/api/profile/avatar`): صورة واحدة حتى 2MB (اقتراح).

### 2.4 التقييم والذكاء الاصطناعي (SRS-5.4.6)

| الثابت | القيمة |
|--------|--------|
| أبعاد التقييم | 5 أبعاد (Technical 25%، Innovation 25%، Market 20%، Team 15%، Documentation 15%) |
| نطاق الدرجات | 0.00 – 100.00 (كل بعد وكل معيار فرعي) |
| التخزين المؤقت (AI Cache) | **24 ساعة** بين تقييمين — `last_evaluation_at` |
| حد إعادة التقييم اليدوي | 3 محاولات/دقيقة لكل مشروع (Rate Limit) + حد 24 ساعة |
| الحد الأقصى للتقييمات المتزامنة | 3 لكل مستخدم في Queue |
| مهلة كل Sub-Agent | 45 ثانية |
| سقف المعالجة المطلق | 180 ثانية (الهدف P95: 120 ثانية) |
| Retry Logic | 3 محاولات: فوري ← 3 ثوانٍ ← 9 ثوانٍ (تأخير تصاعدي) |
| Fallback | OpenAI ← Claude والعكس مع تسجيل السبب |
| نتيجة جزئية | عند اكتمال 3 من 5 أبعاد ضمن السقف |

### 2.5 الاهتمام والاتفاق

| الثابت | القيمة |
|--------|--------|
| `message` في طلب الاهتمام | حتى **500 حرف** — اختياري |
| `rejection_reason` | حتى 500 حرف — اختياري |
| إنشاء مستند الاتفاق PDF | تلقائي عند القبول — خلال < 5 ثوانٍ (BR-05) |
| إعادة محاولة إنشاء PDF | بعد 5 دقائق (UC-07 A1)؛ الفشل النهائي → إشعار مشرف |

### 2.6 سلة المهملات (SRS-F02-06)

| الثابت | القيمة |
|--------|--------|
| مدة الاسترجاع | **30 يوماً** من الحذف |
| الحذف النهائي التلقائي | بعد انتهاء الـ 30 يوماً (أمر مجدول) |

### 2.7 الترقيم والفهارس

| الثابت | القيمة |
|--------|--------|
| حجم الصفحة الافتراضي | **12 مشروعاً/صفحة** (SRS-F07-05) |
| أقصى حجم صفحة | 50 (اقتراح حماية) |
| اقتراحات البحث | حتى **5 اقتراحات** (SRS-F06-02، Debounce 300ms) |

### 2.8 Rate Limits — ملخص المستويات السبعة (rate-limiting-spec.md)

| المستوى | الفئة | الحد | المعرف (Key) |
|---------|-------|------|--------------|
| L1 | المصادقة | 2–10/دقيقة حسب النقطة | email / IP |
| L2 | تصفح عام | 30/دقيقة (burst 10) | IP |
| L3 | صاحب فكرة — قراءة | 60/دقيقة (burst 10) | user_id |
| L3-W | صاحب فكرة — كتابة | 10/دقيقة (burst 5) | user_id |
| L4 | مستثمر — قراءة | 120/دقيقة (burst 20) | user_id |
| L4-W | مستثمر — كتابة | 10/دقيقة (burst 5) | user_id |
| L5 | AI ورفع الملفات | AI: 3/دقيقة/مشروع · رفع: 10/دقيقة | user_id + project_id |
| L6 | مشرف | 60/دقيقة (burst 20) · تصدير 10/دقيقة | user_id |
| L7 | Health/Meta | بلا تحديد | IP داخلي فقط |

رؤوس كل استجابة: `X-RateLimit-Limit` · `X-RateLimit-Remaining` · `X-RateLimit-Reset`؛ وعند 429: `Retry-After` إضافة إلى الهيكل الموحد `{code: "RATE_LIMIT_EXCEEDED", message, retry_after, reset_at}`.

### 2.9 WebSocket (Reverb) — أحداث حرجة فقط

| الحدث | التوقيت |
|-------|---------|
| `interest.created` — طلب اهتمام جديد | فوري لصاحب الفكرة (< 5 ثوانٍ) |

| بقية الأحداث (قبول/رفض/تعديل/إعادة تقييم) | عند إعادة تحميل الصفحة |

قناة خاصة: `private-users.{user_id}` · إنشاء اتصال: 10/دقيقة · أقصى مدة جلسة: 30 دقيقة.
